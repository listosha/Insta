## Что делает движок

Берёт самую раннюю запись со `status: "pending"`, чей слот (14:00 МСК) уже наступил,
публикует страницы гайда **каруселью PNG** в Threads, помечает `published`, и кладёт
ссылку на курс **первым комментарием** (поле `reply`). Один пост за запуск.
Записи со `status: "hold"` пропускаются.

Картинки берутся по `raw.githubusercontent.com/listosha/Insta/main/images/leadmagnets/<folder>/page-NN.png`
(репо публичный, тот же приём, что у IG-каруселей).

# ✅ Триггер cron-job.org настроен (3 июня)

Ежедневный триггер на **14:00 МСК** поднят 3 июня — система полностью на автомате.
№1 уходит сегодня в 14:00, дальше через день. Раздел ниже оставлен как справка по
конфигурации триггера (на случай пересоздания/проверки).

Логика «через день»: движок публикует только в дни, где есть подоспевшая запись, в
пустые дни тихо пропускает — каденс держится датами в очереди, а не расписанием cron.
Бэкстоп воркфлоу (21:30 МСК) подстрахует, если разовый триггер пропущен.

## Справка: конфигурация триггера

## Шаги

1. Зайти на **cron-job.org** → **Create cronjob**.
2. **Title:** `Threads lead magnet 14:00`.
3. **URL:**
   ```
   https://api.github.com/repos/listosha/Insta/actions/workflows/publish-threads-leadmagnet.yml/dispatches
   ```
4. **Request method:** `POST` (в разделе Advanced / Request).
5. **Request headers** (те же, что у существующих триггеров публикации):
   ```
   Authorization: Bearer <PAT «Insta pub trig»>
   Accept: application/vnd.github+json
   X-GitHub-Api-Version: 2022-11-28
   ```
   PAT тот же, что у каруселей и текстовых Threads — у него уже есть Actions: Read+write.
6. **Request body:**
   ```
   {"ref":"main"}
   ```
7. **Schedule:** каждый день, время **14:00**, таймзона **Europe/Moscow**
   (если cron-job.org в UTC — поставить **11:00 UTC**, Москва = UTC+3 без перехода на лето).
8. Сохранить. **Успешный ответ GitHub = HTTP 204** (видно в логе выполнения cron-job.org).
