# Pinterest для проекта: технический и контентный анализ

_Дата: 2026-06-01. Источник: deep-research (105 агентов, 24/25 фактов подтверждены 3-0 по первичной документации Pinterest Developers) + добивающие веб-поиски по РФ-доступности и спецификациям пинов._

## TL;DR

**Технически — да, автопостинг в Pinterest встраивается в нашу текущую схему** (GitHub Actions cron + официальный API + рефреш токена) почти один-в-один как Threads/Instagram. Но есть **три реальных барьера**:

1. ✅ Официальный **Pinterest API v5** умеет создавать пины (фото/видео) и доски, ставить **кликабельную ссылку на лендинг** — главное, что нам нужно.
2. ⚠️ Чтобы пины **были видны не только автору**, нужен апгрейд `Trial → Standard` через **ручную модерацию с видео-демо OAuth-флоу** — барьер тяжелее, чем у Threads.
3. ⚠️ **Pinterest в РФ не заблокирован формально, но его «замедляют» волнами** и он не в «белом списке» — органический трафик из России нестабилен. Это бьёт по смыслу затеи для РФ-аудитории.

## 1. Техническая сторона / API

### Есть ли API и что умеет
**Pinterest API v5 — живой официальный публичный API** (verified 3-0). Эндпоинты:
- `POST /v5/pins` (`pins/create`) — создать **image или video** пин;
- `POST /v5/boards` (`boards/create`) — создать доску.

Официальный референс-репозиторий: **github.com/pinterest/api-quickstart** (Python/JS/PHP/Bash).
Док: `developers.pinterest.com/docs/work-with-organic-content-and-users/create-boards-and-pins/`.

> Idea Pins (Story-формат) через API создавать **нельзя** — API только под обычные image/video пины. Для нас норм: наши слайды — статичные пины.

### Доступ, OAuth, скоупы
- **OAuth 2.0 user-authorization** (как Threads), грант **Authorization Code**.
- Нужны **`pins:write` + `boards:write` одновременно** (verified — без `boards:write` пин не создаётся), плюс read-скоупы для получения board ID. Есть `_secret`-варианты для приватных пинов.
- Док: `developers.pinterest.com/docs/getting-started/set-up-authentication-and-authorization/`.

### Токены
- **access-token: 30 дней** (2 592 000 сек);
- **refresh-token: 60 дней, обновляется бесконечно** (continuous refresh).
- → Нужен такой же рефреш-воркфлоу, как у Threads (`refresh-threads-token.yml`). Легаси 365-дневные токены для новых приложений больше не дают.

### 🔴 Главный барьер: Trial vs Standard
Verbatim из доков: **«all Pins and Boards created with Trial access are only visible to their creator as Sandbox entities»**.

На стартовом Trial автопостинг работает технически, **но пины никто, кроме автора, не видит**. Для публичности — **апгрейд до Standard**:
- приложение уже одобрено на Trial и соответствует Developer Guidelines;
- **видео-запись рабочего OAuth-флоу** (экран авторизации → обмен токена → authenticated API call). Частый отказ: «Demo video does not show the authentication flow»;
- **ссылка на публичную privacy policy**;
- срок рассмотрения **~1–4 недели**.

### Rate limits — для нас не проблема
- Trial: **1000 запросов/день на всё приложение**;
- Standard: **100 запросов/сек на юзера**.
- Нам нужно несколько пинов в день → запас огромный.

### Ссылки на лендинг — поддерживаются
Пин несёт **destination URL** (поле `link`) → клик ведёт на наш сайт/лендинг. Это нативная фича (в IG ссылки в постах не кликабельны). Rich Pins подтягивают метаданные с сайта-источника через Open Graph / schema.org — отдельный механизм.

### Легальность автоматизации
**Headless-постинг по cron через официальный API легален** (verified) — регулируется отдельным Developer & API ToS. Запрет на «автоматический доступ» в потребительском ToS касается **скрейпинга/чтения**, не публикации через API. Риски бана — за нарушение **контентных** политик: ограничение аккаунта (напр. запрет постинга на 14 дней) или удаление даже **за одно грубое нарушение**.

### Альтернатива самописному API — сторонние планировщики
Отложенный постинг пинов со ссылками умеют: **Publer** (официальный API на Business/Enterprise, пины с destination URL), **Tailwind** (офиц. партнёр Pinterest, bulk, SmartSchedule), **SocialPilot** (CSV bulk до 500 пинов), **Hootsuite** (Bulk Composer). Они сами ходят в Pinterest API — это обход нашей DIY-интеграции и app-review, а не API. (Слух про «Metricool переписывает все ссылки» — **опровергнут** 0-3.)

## 2. Доступность в РФ — слабое звено 🔴

По свежим данным (фев.–весна 2026):
- **Формально НЕ заблокирован** — Роскомнадзор не внёс в реестр, открывается без VPN.
- **НО** периодически **«замедляют» волнами** (сбои по регионам окт. 2025, фев. 2026) и **не в «белом списке»** — при отключениях мобильного интернета не работает.
- Дек. 2025: Таганский суд оштрафовал Pinterest на 6 млн ₽ за неудаление контента → тренд на ужесточение, риск полной блокировки ненулевой.

**Вывод:** органический трафик из РФ нестабилен. Аргумент против Pinterest как основного канала на РФ-аудиторию.

Где имеет смысл:
- **русскоязычная аудитория вне РФ** (СНГ, эмиграция, Европа, Израиль) — работает стабильно;
- **«вечнозелёный» SEO-канал**: пин живёт месяцами-годами, приводит трафик из поиска Pinterest и Google Images;
- кириллица индексируется, русский сегмент Pinterest тонкий — низкая конкуренция, но и ниже спрос.

## 3. Формат и содержание картинок

### Размеры и форматы (verified поиском)
| Формат | Размер | Соотношение |
|---|---|---|
| **Стандартный пин (оптимум)** | **1000×1500** | **2:3** |
| Long pin | 1000×2100 | ~1:2.1 |
| Инфографика | 1000×3000 | до 1:3 |
| Квадрат | 1000×1000 | 1:1 |
| Idea Pin (только приложение) | 1080×1920 | 9:16 |

- Файл: **JPG/PNG/WebP, до 20 МБ** (рек. <5 МБ). **PNG лучше для графики с текстом** — наш случай.
- **Pin title: до 100 символов**; **Pin description: до 500** (в ленте видно первые ~50 — ключевое в начало). У виральных пинов 2025 описания ~220–232 символа.

### Наши слайды 1080×1350 (4:5) vs идеал 2:3
Наши слайды **4:5** — технически валидный пин, загрузится. Но Pinterest оптимизирован под **2:3 (1000×1500)** — выше CTR. Для максимума — **отдельный вертикальный шаблон 1000×1500** в рендере (правка viewport в `render_carousels.js` + вёрстка). Для теста можно стартовать на 4:5.

### Что работает (Pinterest = поисковик, не лента)
Заходит контент, который **полезно сохранить**:
- инфографика-памятки, чек-листы, таблицы;
- списки: «10 продуктов с железом», «7 признаков дефицита магния»;
- рецепты (топ-категория Pinterest), особенно healthy-meal;
- гайды-однопины с заголовком-обещанием результата.

Наша ниша (нутрициология/БАД/меню) — **идеальное попадание**. Один слайд = один пин; из карусели на 8 слайдов → 8 пинов + сводный.

### Overlay (текст на картинке) — обязателен
На Pinterest крупный заголовок-обещание на самой картинке критичен для CTR, читаемый в мелком превью. У нас это уже есть в шаблонах.

### Title / description — это SEO
- Естественные ключевые слова («продукты с железом», «дефицит железа симптомы», «меню при анемии»).
- Хэштеги — низкий приоритет (работают ключевые слова в тексте).
- Description можно генерировать кодом из тех же данных, что и слайд.

### ⚠️ Политики по здоровью и БАД
- **Жёсткие запреты на БАД/похудение касаются платной РЕКЛАМЫ (Ads)**, не органических пинов (verified): нельзя рекламировать «weight loss / appetite suppressant pills, supplements», нельзя claims о профилактике/лечении болезней.
- Для **органических** пинов формального запрета на тему БАД нет, **но** medical-claims рискованны по Community Guidelines (health misinformation) → возможны ограничения.
- **Практика:** в тексте пинов — **без «лечит / вылечивает / гарантированное похудение / заменяет врача»**. Формулировки образовательные. Платную рекламу БАД на Pinterest не закладываем.

### Частота и дубликаты
- Оптимально — несколько пинов в день равномерно (Pinterest любит регулярность). Cron-подход идеально ложится.
- Один контент можно постить на разные релевантные доски, но с интервалом и вариациями (другой заголовок/обложка) — иначе спам.

## 4. Практический вывод

**Встраивается в текущую схему?** Да, архитектурно один-в-один с Threads:
- `publish-pinterest.yml` (cron) → читает `pinterest-schedule.json` → `POST /v5/pins` с `board_id`, `media_source`, `title`, `description`, `link`;
- `refresh-pinterest-token.yml` — рефреш по аналогии с Threads;
- картинки — переиспользуем рендер, добавив вертикальный шаблон 1000×1500.

**Переиспользовать слайды 1080×1350?** Для старта да; для CTR — добавить 2:3.

**Стоит ли игра свеч?**
- 🟢 ЗА: дешёвый прирост канала (переиспользуем контент и инфраструктуру), **кликабельные ссылки на лендинг** (чего нет в IG), **вечнозелёный SEO-трафик**, ниша «питание/рецепты/памятки» — родная для Pinterest.
- 🔴 ПРОТИВ: **нестабильная доступность в РФ** обнуляет часть смысла для российской аудитории; разовая возня с app-review.

**Рекомендация:** запускать имеет смысл, **если цель — русскоязычная аудитория вне РФ + долгосрочный SEO-трафик на лендинг**, не охват внутри России. Это не замена IG/Threads, а **дополнительный low-effort канал на переиспользованном контенте**. Начать дёшево: 2–3 недели через Publer/Tailwind (без app-review), замерить трафик/сохранения — и если зайдёт, вкладываться в полную API-автоматизацию.

## Что нужно сделать ОДИН РАЗ перед автопостингом (чек-лист доступа)

1. Перевести аккаунт в **бизнес**.
2. Зарегистрировать **приложение** → получить `app_id` / `app_secret`.
3. Пройти **OAuth-флоу** вручную один раз → получить первый `refresh_token`.
4. 🔴 Подать заявку **Trial → Standard**: видео-демо OAuth-флоу + публичная privacy policy + ожидание ~1–4 недели. _Без этого пины видны только автору._
5. Положить токены в **GitHub Secrets**, включить cron-воркфлоу.
